# Local review harness

The scripts under `src/` preserve the finite G0/G1 and block-comparison methodology.
They are a source-only review harness for a frozen native checkpoint contract, not
an arbitrary-scene benchmark. This repository deliberately contains no experiment
data or generated readiness/performance verdicts.

## Prepare an isolated workspace

```bash
python -B gpu_accelerate/prepare_workspace.py \
  --workspace /path/outside/repository/replay-workspace
```

This copies code and documentation only, creates empty data/output directories,
and sets performance authorization to false. It never copies a scene, initializes
CUDA, or changes the original worktree. Run the build script from this repository
with an external `--output`, then place the resulting libraries in the workspace's
`build/` directory. Release and guarded builds use distinct library names.

`src/workspace_paths.py` supports these environment settings:

| Setting | Purpose |
| --- | --- |
| `BM_GPU_WORKSPACE` | Data/output root; defaults to the parent of the script's `src/` directory |
| `BM_INFINIGEN_ROOT` | Existing Infinigen repository root for Python imports |
| `BM_NATIVE_REFERENCE_ROOT` | External original-capture and independently established oracle root; defaults to the workspace |
| `BM_PYTHON` | Python used by profiler targets; defaults to the current interpreter |
| `BM_NCU`, `BM_COMPUTE_SANITIZER` | Explicit tool executable overrides; otherwise PATH |
| `BM_NCU_SECTIONS` | Nsight Compute sections directory, required for profile collection |
| `BM_GPU_TMPDIR` | Owned temporary directory; use a native Linux filesystem for WSL profiler IPC if needed |

Activate the intended Python/CUDA environment first. `run_stage.py` preserves its
PATH and dynamic library paths, isolates generated caches, logs each command,
and runs one fresh subprocess per explicitly requested phase. It does not install
software, elevate profiler permissions, or retry failed CUDA contexts.
Python correctness tools require NumPy (`requirements-checks.txt`); the original
Python call path additionally requires the normal BinocMesher/Infinigen dependencies.

## Direct natural-input correctness

`check_gpu_solver.py` accepts an external native capture directory, parameter NPZ,
parameter SHA-256, bridge and solver libraries. It checks all five execution modes,
repeat/reset behavior, trace noninterference and bitwise complete outputs.
For example, after choosing `BM_GPU_WORKSPACE` and activating the runtime:

```bash
python -B gpu_accelerate/src/check_gpu_solver.py --scope natural \
  --capture-dir /path/to/native-capture --K 3 \
  --parameters /path/to/field_parameters.npz \
  --parameters-sha256 YOUR_VERIFIED_PARAMETER_SHA256 \
  --bridge /path/to/libfield_bridge.so \
  --solver /path/to/libgpu_solver_b128.so \
  --out "$BM_GPU_WORKSPACE/results/correctness-new"
```

Output paths must be fresh and inside the chosen workspace. `--scope diagnostic`
uses explicitly labelled analytic fixtures; it is not a substitute for the natural
capture/real-field test above. The repository does not distribute either the real
capture or the scene parameters.

## Full native and paired comparisons

The existing harness expects these separately prepared, local-only artifacts:

- `inputs/accepted_scene/inputs.npz`: camera and scene arrays consumed by the
  original Python entry; `field_parameters.npz`: original typed field parameter arrays.
- `inputs/checkpoint_seed/`: complete original checkpoint, including native state.
- `configs/scene.json`, `FROZEN_MATRIX.json`, and `BLOCK_MATRIX.json`: the caller's
  frozen scene/configuration and native case inventory, with capture paths, input
  hashes, K, N/M, endpoint counts, calibration/held-out roles, and finite protocol.
- `upstream/main/`: an isolated copy of the original Python/native BinocMesher tree,
  with the instrumented `binocmesher/lib/core.so`; existing Infinigen is referenced
  through `BM_INFINIGEN_ROOT` or `upstream/infinigen/`.
- Under `BM_NATIVE_REFERENCE_ROOT`: `runs/g0_observed_01/capture` and
  `runs/g0_observed_K6_01/capture`, plus independently established
  `results/correctness/gpu_natural_01/<case>/oracle.npz` and
  `results/correctness/gpu_natural_K6_01/<case>/oracle.npz` for full native validation.
  These are reference inputs, not generated by the solver under test.
- `build/`: field bridge and selected release/debug solver libraries. The full
  G0/G1 suite uses `libgpu_solver.so`; the block suite uses `libgpu_solver_b*.so`.

`native_capture.cpp`, `native_checkpoint.cpp` and `native_common.cpp` must be linked
into the **same** `core.so` as the original BinocMesher sources: loading a second
copy would create different global native state. `capture_hooks.py` checks that
identity and records natural inputs/rounds/outputs. The two `check_*native*.cpp`
files contain the CPU replay checks. Sanitizer replay builds use ASan/UBSan and
`-fno-pie -no-pie`; this is a checker build setting, not an algorithm change. Native
helpers are not enabled in the main repository's default build by this publication.

`common_runtime.py` / `common_runner.py` preserve the original group loop and
adapt GPU outputs to accumulated xyz, times, tags and vertex_map. The complete
entry timing includes checkpoint reads, field/solver preparation, transfers,
solve, readback and cleanup; it stops before final mesh writing. Pre-copying a
private checkpoint is outside timing. Process/import and filesystem caches may
be reused, so this is not a fully cold-cache measurement.

`performance_suite.py` implements the original finite comparisons including CUDA
Graphs; `block_benchmark.py` compares only fixed GROUP32 blocks 256/128/64. The block
protocol requires the previously defined two-field, K=3/6 checkpoint shape and
uses first batches only to calibrate shared repeats. It intentionally refuses a
mismatching scene matrix instead of relabelling an arbitrary scene as covered.
`check_block_variants.py` checks all frozen natural cases before timing. Authorized
performance needs `configs/PERFORMANCE_AUTHORIZATION.json` with `allowed: true`;
the G0/G1 suite also checks the workspace readiness verdict. Running the preparation
or `--help` paths is not a GPU test.

The fixed comparison performs three sequential processes, balanced AB/BA pairs,
and output checks outside each timing arm. `audit_block_results.py` and
`audit_performance_results.py` independently recompute saved results. `run_block_profiles.py`
requires a completed suite and an audit matching that suite and its hashes; invoke
it with explicit `--performance`, `--audit`, `--out`, and `--execute-profile` after
formal timing has stopped. `ncu_csv.py` handles the raw wide and long CSV layouts.
Profiler counters and replay durations are diagnostic, not substitutes for paired
complete-solve timing. No captured input, output or measured result is committed.
