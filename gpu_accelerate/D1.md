# D1: split SdfTrees evaluation

D1 evaluates the real procedural SdfTrees field and advances the original
GPU-resident bisection using its newly calculated SDF. It splits each field call
into classification, independent descriptor construction, and point evaluation.
Every query/lattice request constructs its own descriptor, including repeated
cells. D1 does not deduplicate or reuse answers across calls or solves.

## Source map

| File | Responsibility |
| --- | --- |
| `src/d4_field_eval.cuh` | `classify`, `construct`, and `evaluate`; exact field mathematics and descriptor layout |
| `src/d4_pipeline.cuh` | Device allocations, kernels, diagnostic checks, and `eval(..., mode=1, ...)` |
| `src/d4_solver.cu` | Independent handle, center evaluation, actual query generation, K bisection rounds, final-right evaluation and output |
| `include/d4_solver_api.h` | Public C ABI; D1 is variant 1 |
| `src/gpu_solver.cu` | Unmodified original CSR geometry, bisection update, witness and output implementation |
| `src/field_eval.cuh`, `src/field_types.h`, `src/field_bridge.cu` | Unmodified original field dispatch, field ABI and parameter upload |
| `build_d1.py` | Portable strict release/debug builds, including original references |
| `src/check_d4_gpu.py` | Bitwise reference/field/solver checks; defaults to D1 only |
| `src/replay_d4_difference.py` | Replay a saved first numerical difference using its saved geometry/parameters |

The `d4_` filenames and symbols are intentional. They preserve the tested shared
implementation byte for byte rather than extracting and rewriting D1 for this
publication. The library also contains D2/D3 implementations; select **variant
1** for D1. This publication adds no D2/D3 performance or integration entry.
`D1_SOURCE_MANIFEST.json` records the four preserved source/API hashes and the
fixed upstream revision. Graph extensions and historical experiment runners are
not part of this addition.

## Execution and numerical contract

For q actual query points and L lattices:

1. `classify_kernel` assigns one thread to each query/lattice pair and runs the
   original Voronoi classifier. Its 20-byte key retains lattice, original hash and
   all three raw float center bit patterns.
2. `construct_kernel` independently constructs one 24-byte descriptor per
   request: enabled mask, adjusted center, radius and ratio. This computes the
   real mask/noise and enabled cell-center LandTiles calls.
3. `evaluate_kernel` assigns one thread per query. It visits lattices in the
   original order, retains strict `<` selection, evaluates point LandTiles and
   Perlin, and writes SDF plus all three aux columns.

The new field kernels use 128 threads per block. Original solver kernels keep
their original launch configurations. The ordinary D1 production path skips
sorting, grouping, miss lookup and mapping restoration. Classification still
writes the shared scratch layout; D1 has not been specialized to eliminate all
unused shared buffers. Diagnostic D1 runs additionally group keys for work-count
validation; those diagnostic operations are disabled for normal execution.

`d4_enqueue` resets the pipeline and original bisection state on every solve,
evaluates all centers, then performs K actual midpoint rounds and a final-right
field evaluation. The total field-query count remains `N + (K + 1) * M`.
Double source geometry, the original `center*(1-t)+endpoint*t` expression and
float conversion point, sign decisions, original-rank witness and final float3
are retained. Saved SDF, future query coordinates and oracle outputs are never
candidate inputs.

## Build

Use the existing Linux/WSL CUDA installation and original Infinigen headers;
see [BUILD.md](BUILD.md) for the dependency and strict floating-point contract.
The preserved shared implementation requires the CUB headers supplied by CUDA.
The tested configuration used CUDA 13.1, CUB 3.1.4 and `sm_120`; another toolkit or
GPU requires rebuilding and running the correctness gates on that environment.

From the repository root:

```bash
python3 -B gpu_accelerate/build_d1.py \
  --nvcc /path/to/cuda/bin/nvcc \
  --host-compiler /path/to/g++ \
  --infinigen-include /path/to/infinigen/infinigen \
  --output ../d1-build-release
```

This produces `libfield_bridge.so`, `libgpu_solver_b128.so`, and
`libd4_solver.so`. Use a separate output directory and `--debug` for
`libgpu_solver_b128_debug.so` and `libd4_solver_debug.so`; the bridge filename is
unchanged. `--dry-run` prints commands without compiler execution or writes.
The output directory must be outside the checkout and new or empty. Full compile
commands, source/header hashes, compiler output and library hashes are retained
there. Both builds use `-O3`, strict floating-point flags, and no CUDA `-G`.

## API

Include `gpu_accelerate/include/d4_solver_api.h`. Create the field through the
existing field bridge, then call `d4_solver_create` with its borrowed FieldView,
ordered CSR offsets, double centers/endpoints and a maximum K. Run D1 with:

```c
d4_solver_run(handle, 1, K, 0, 0); /* D1, trace off, diagnostic counters off */
```

Check every return code. The run call synchronizes before returning. Use
`d4_solver_readback` for the same eleven output buffers and optional-trace rules
documented in [API.md](API.md); use `d4_solver_destroy` when finished. Link the
D4 library for these symbols and the field bridge for field lifecycle functions.
The included original solver symbols are renamed internally to avoid binding the
candidate to a separately loaded reference solver by symbol interposition.

The new handle supports SdfTrees (`FieldView.kind == 4`), 1 through 256 lattices,
and `0 <= K <= max_k <= 6`. Its field and geometry are immutable. Use the creating
CUDA device/context, serial calls and the same live field allocation; destroy the
solver before destroying its field. A different parameter instance requires a
new handle. Every solve resets logical state; error flags stay sticky until
destroy. Checked allocations include keys, descriptors, mappings, sort/scan and
diagnostic buffers. They respect the shared 70% free-memory budget with field
assets already resident. D1 currently retains the common D4 scratch allocation.

## Correctness and first-difference replay

The checker requires separately supplied original parameters and two captures,
each containing five natural SdfTrees batches for K=3/6. Optional independent
oracle directories are checked against the captures before candidate execution.
Even diagnostic scope derives its finite fixtures from these supplied inputs;
it is not a data-free synthetic substitute for real-field validation.

```bash
python3 -B gpu_accelerate/src/check_d4_gpu.py \
  --phase all --scope all --variants 1 \
  --capture-k3 /path/to/k3/capture \
  --capture-k6 /path/to/k6/capture \
  --oracle-k3 /path/to/k3/independent-oracles \
  --oracle-k6 /path/to/k6/independent-oracles \
  --parameters /path/to/field_parameters.npz \
  --parameters-sha256 EXPECTED_SHA256 \
  --bridge ../d1-build-release/libfield_bridge.so \
  --reference-solver ../d1-build-release/libgpu_solver_b128.so \
  --candidate-solver ../d1-build-release/libd4_solver.so \
  --out ../d1-check-release
```

The default `--variants` is `1`. `--phase all` first validates frozen R0/R1/L1_B128
and then D1 on all selected inputs. The checker compares actual float queries,
all SDF/aux bytes, signs, double bounds, witness/valid/final float3, independent
original key/descriptor bytes and actual GPU work counts. It checks first,
repeated and trace/counters-off runs plus same-handle K changes. For a debug
build, substitute both debug solver filenames and add `--expect-debug`.

Every output directory must be new and outside the checkout. The checker writes
input/build fingerprints and raw evidence, stops at the first failure, and saves
a `first_difference` bundle when it encounters a numerical difference. Replay it
with explicit libraries and a new output directory:

```bash
python3 -B gpu_accelerate/src/replay_d4_difference.py \
  --difference ../d1-check-release/first_difference --variant 1 \
  --bridge ../d1-build-release/libfield_bridge.so \
  --reference-solver ../d1-build-release/libgpu_solver_b128.so \
  --candidate-solver ../d1-build-release/libd4_solver.so \
  --out ../d1-difference-replay
```

This publication does not bundle scene data, measured performance, compiler
environments, binaries or third-party trees. A build success alone is not a
numerical or speed claim. These APIs do not automatically replace the main
meshing pipeline, and the solver checker does not validate the full native
checkpoint-to-output entry.

Publication verification (2026-09-13): the portable entry rebuilt release and
debug bridge/reference/candidate libraries. Each build passed all 10 natural
and 11 diagnostic cases: 201 frozen-reference records and 67 D1 records,
including first/repeated, trace-off and same-handle K-switch checks. The replay
entry received syntax/help checks; no normal numerical difference was produced
to replay. This publication did not rerun performance, sanitizer or the full
native common-entry matrix. Raw validation records remain outside this checkout.
