# Forest component sequence v1 — fixed protocol

This experiment extends, and does not overwrite, the frozen per-event Forest
admission artifacts. The denominator is all 131 canonical events at roots 3/2
and 5/2, including all 100 independently rejected events. Inputs, original
SourceVID observer ABI v2, source selectors, contact policy, and actual binary32
geometry remain unchanged.

## Support graph and atomic policy

The graph is a conservative dependency supergraph for the fixed requested
schedule and current source-selector domain. An edge means independence has
not been established; it is not necessarily a geometric collision. Include
original owner, source-face, boundary identity, retained-interface face/link
dependencies, and actual-query spatial support overlap across all elements.
Ideal affine bounds alone must not exclude actual binary32 interactions.

The one event with no source contract permanently reserves its complete current
candidate V-halo as baseline-only support. This does not define or bound an
unknown future replacement. Missing actual support evidence conservatively
connects the affected event to every event at the same root; never treat it as
empty support. Every missing-evidence connection is explicitly reported.

Each connected component is an admission unit. Any independently rejected
member causes the whole component to fall back. Shared modified faces, raw
owners, or boundary vertices are unsupported in v1: no generic overlap solver
is added. Otherwise compile all members from the same immutable baseline and
add exact replacement–replacement checks. Previously certified replacement–
retained checks can be inherited only with matching source/query/baseline
bindings, since the jointly retained set is a subset of each individually
retained set. Cross-component independence is also checked before publishing.

## Execution and evidence

First establish complete component schedule admission. Then actually construct
one combined five-element scene for each of the 64 original natural timestamps.
The two exact roots are additional diagnostics and never enter natural-frame
denominators. Fresh centers are canonically indexed per element. No sequential
application to already modified baselines, partial component publication, or
cross-frame state reuse is allowed. Compare OMP 1 and OMP 8 outputs.

Report root resolution separately from nonempty treated root coverage;
all-baseline fallback is not a successful nonempty treatment. Report component
and jointly admitted event counts, modified natural-frame counts, fail-closed
reasons, and certification/playback/audit costs separately. Array construction
and hashing in a research harness are not production performance measurements.

## Visibility and scope

After combined sequence verification, use the original rendering camera for
cheap depth, normals, and component/event IDs. Keep its provenance separate
from the relaxed LOD camera used to generate and certify the native geometry.
Include all candidates in visibility denominators; unavailable visibility is
unknown, not invisible. This remains pre-displacement opaque geometry.

Any later post-displacement pilot is separately versioned and must explicitly
define center attributes, displacement evaluation, shared boundary identity,
and post-displacement contact certification. Do not overwrite build_complete=
false, relax contact policy, run long videos, or claim visual improvement from
geometric differences alone.

## Resource controls

Keep one scene in memory; RSS limit 8 GiB. Private cache copies are at most
2 GiB and removed after full original-input verification. Initial new compact
reports are limited to 100 MiB; visibility images to 128 MiB. Do not persist
64 full mesh files. Preserve earlier evidence and environments. Total local
repository/environment/backup footprint must remain below 400 GB.
