# Follow-up certificate experiment, not a change to the geometric treatment

The v2 fixed four-demo run completed all 26 units. It retained 129 UNKNOWN
unit/triangle pairs and 30 restrictive rejections. No runtime window was
admitted. Its scripts and result files are preserved as versioned evidence.

An exact read-only diagnosis of E2's seven distinct unresolved candidate types
found two generic sufficient certificates: oblique strict hull separation and
spatial separation of the zero feature of a supporting XY half-plane. The new
v3 module is tested on synthetic positive/negative inputs before re-running
the SAME four events, windows, anchors, source coordinates and actual singletons.
No event-specific VID, normal, coefficient or passing outcome is hardcoded.

The fixed direction family uses two nonzero coordinate components, integer
ratios 1:k or k:1, k=1..8, both relative signs. A candidate is accepted only
after exact verification over the complete affine branch. Other directions
may remain unsupported. The zero-feature rule permits only identically-zero
or strictly-outside projected vertices, and requires independent exact spatial
separation of every undeclared zero-feature vertex. Isolated roots, equality
without declared identity, or unproven shared-face regularity never pass.

Re-run v3 into a NEW output directory, retain v2, and report both complete
denominators. Lower UNKNOWN counts measure certificate coverage, not improved
geometry, successful runtime coverage, SSIM or paper novelty. Binary32,
extra_smooth, event isolation and actual identity gates stay separate.

The parallel Forest change is also explicit: the first 24-frame attempt stopped
at an exactly 128 MiB provenance file due to our own RLIMIT_FSIZE, not a discovered
geometry error. Its temporal level zero is structurally inadequate for the
target temporal-neighbour saddle. Preserve that STOP, do not count it as zero
events. The next fresh build uses the same seed/LOD and fixed earliest 64 frames,
two temporal groups, a 45-minute wall limit, 3 GiB total incremental budget,
2.5 GiB early stop and 512 MiB single-file cap. This change is based on the time
tree and diagnosed resource failure, not on event count or measured quality.
